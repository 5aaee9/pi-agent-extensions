# pi-provider-sub2api verification

Scenario files: `scripts/e2e/pi/pi-provider-sub2api*.e2e.ts`, 80 scenarios. Support: `servers-sub2api.ts`, `servers-sub2api-replies.ts`, `pi-provider-sub2api-{support,modes-support,catalog-support,xai-support,compaction-support}.ts`. Every regression ran through `mut.sh` against the packed and installed package, and `git diff --stat` afterwards showed only the intended changes. "fail=N" is what the runner printed for the named scenario, with the source mutated.

## Findings

**Regressions a first run did not detect, and why.**

- `lifecycleController.abort()` removed passed P5: the request's own 30-second timeout closed it too, and the scenario only waited for a close. It now has a 10-second bound, and the mutation fails.
- `escapeConfigLiteral` unescaped passed P1 token forms: the scenario checked only requests that arrived, so a turn that never left passed. It now requires one model request per relay, and both mutations fail.
- Tiers unscaled passed P8: the chosen catalog model had no tiers. P7 billing now seeds a tiered price, and the mutation fails.
- Three first attempts were wrong mutations, replaced and then detected: rewriting `include` while leaving replay intact, clearing a mode on the already-selected xAI model, and a sticky tier that the scenario's order masked.

**Regressions still not detected, recorded as equivalent on a real host.**

- `normalized.end()` removed from the stream wrapper: an `error` or `done` event already completes the stream. The call only matters for a source ending without a terminal event, which the adapter does not produce.
- `pending` removed from `pending || !ctx.isIdle()`: `isIdle` is already false during a running compaction, so only removing both guards fails (it does).
- `requestFooterRender` removed from `model_select`: the scenario still passed, with the badge changing in the terminal. Likely because Pi repaints the footer itself on a model change. The audit row asserted the call on a stand-in; the visible badge change stays covered.
- The `catch` in `loadCachedModelMetadata` made to throw: the malformed-cache scenario still passed, likely because `ModelRuntime.create` tolerates a malformed store so the catch is not on this path. Two replacement mutations fail it: the store file rewritten, and the store parsed outside the guard.

**Audit deviations.** Final counts match the design: 40 DELETE, 155 to E2E, 97 stays; `npm run check` reports 97 passed, and no test references `as unknown as ExtensionAPI` or stubs `fetch`.

- `XAI_API_KEY` is a third placeholder in P8, beside the two the design names, because the bundled xAI comparison needs Pi to list xAI's built-in models. It stays inert: those scenarios are offline.
- codex-compaction L322: the duplicate block is covered. Its forced interleaving of an unrelated compaction during a command is not, because only the stand-in produced it; the sticky-override mutation covers the override leaking to a later compaction.
- sub2api L1567: the abort is covered. "Not published afterwards" is not observable, as the audit noted of the original.
- xai L812: `onResponse` and the caller's `cacheRetention` option have no route from an extension and are not asserted. The header opt-out is covered through `before_provider_headers`.
- sub2api L409 and model-cache `redirect: "error"` and signal assertions became observable behaviour: a 302 from the relay is not followed on discovery, Codex turns, xAI turns, or compaction. Signals are covered only by the usage abort and timeout.
- Online billing scenarios price a fake model seeded into `models-store.json`, so they assert no value from Pi's live catalog.
- Harness: `Reply.onClientClose` added to `servers.ts`, and `startServer` split into `eventArgs` and `onAbandon` to stay within the 50-line limit, with no behaviour change. `pi-continue`, `harness`, and `cross-package` scenarios pass on it.
- `until` polls every 50 ms for four waits: a cache write, a later provider registration, and stderr text. `docs/rpc.md` and `docs/rpc-commands.md` describe no event for these.

**Decisions and limits worth the owner's eye.**

- `stream_read_error` normalization works on the final message text. A relay sending `code: "stream_read_error"` with a different non-empty `message` is not retried, because the adapter drops the code when a message exists. This is not one of the three wire shapes and was not seen; it is not handled.
- With defect 8 fixed, a `sub2api.json` that fails to load at `/reload` also removes the relays, matching a fresh start. After removal `ctx.model` stays set, and a prompt is rejected with Pi's `No API key found for relay`, which the scenario does not pin.
- Offline, no usage row is shown rather than a stale or "unavailable" one. `/sub2api-refresh` still reaches the relay; a scenario guards that. `honour-offline-mode` is written as a new capability, though it also narrows the background refresh `model-discovery-cache` requires; a `MODIFIED` entry there may be the better shape when it is archived.
- 796eeb2 (five-minute compaction timeout) stays an accepted gap, per the design.

**New defects.** None beyond the register, except that defect 8's refresh path was confirmed on the wire, where the audit had only inferred it.
