# Proposal

## Why

`@indexyz/dsh-autocompact` is the dsh (DeepSeek Harness) port of `@indexyz/pi-autocompact` that already works: it sets an earlier automatic-compaction threshold for the current session and model, edits the deployment's persisted defaults from a Settings page, and shows the session's threshold and measured pressure in the composer's ambient row. It lives in the sibling repository `dsh-agent-extensions`, which has its own workspace, lockfile, and scripts; keeping it there splits one person's plugin family across two repositories with two release processes, and leaves the ported package's sibling in a repository that has no release engine. This repository is its home, and its repository-wide change `support-dsh-packages` adds the class and the release verification it needs. This change adds the package.

## What Changes

- **The package `dsh-autocompact/`**, published as `@indexyz/dsh-autocompact` at version `0.1.0`: a `dsh` manifest (`dsh.bundle.patch` pointing at `cordis.patch.yml`, `dsh.client` declaring the web platform, immediate loading, and its injected `@deepseek-ai/dsh-client-*` services), `main`/`types`/`exports` at the built `lib/`, `files` shipping `lib`, `src`, `client.js`, `cordis.patch.yml`, `README.md`, `CHANGELOG.md`, and `LICENSE`, and its own `tsconfig.json`, `tsconfig.build.json`, `tsdown.config.ts`, and `vitest.config.ts`.
- **The host half** registers the session-scoped `/autocompact` command: it sets an explicit absolute token threshold for the current session and the exact routed `provider/model`, from `300k`, `1m`, or an absolute count (`/autocompact off` suppresses the global default for this session, `/autocompact default` clears the session override), reports the effective threshold and the backend's own automatic-compaction state, validates the threshold against the backend's retained tail and the model's real context window, and writes no configuration, no session log entry, and no model metadata. Optional read-only global defaults come from the bundle row's `Config` (`modelLimits`, `enabled`, `retainTokens`).
- **The pressure check** on `agent/pre-step`: it measures the request with `ctx.tokenMeter`, compares it with the effective threshold for the agent's exact route, and above it asks the agent's own compaction backend to compact an explicit balanced surface range through `ctx.compaction.compactRegion`, preserving the retained-tail policy the backend publishes, never splitting a tool call from its result, injecting no prompt, and never aborting the turn. A backend whose `config.auto` is `false`, a backend without `compactRegion`, a missing context window, and a failed summary each leave the session untouched and are reported once per session.
- **The Settings section** (`settings.section`, id `@indexyz/dsh-autocompact`): a master switch and one editable row per exact `provider/model` route, plus an add-model control fed by the live model catalog with a manual route field when the catalog is unavailable. It reads and writes the bundle row through the `remote.settings` namespace as its own injected Cordis service, guarded by the row revision (a conflict reloads the current values), rendered read-only when the profile is not writable, with its own crash boundary.
- **The composer status pill** (`conversation.composer.dock`): it reads the session's route from the `modelSelection` projection and the measured pressure from `contextPressure`, shows `128K / 300K`, the threshold alone, or `Off`, takes no seat when no threshold applies, and on click opens Settings on this plugin's section by resolving the settings shell's store seat through the slot registry and invoking its own `openSection`, falling back to the central panel this plugin registers under the same key. Both paths are guarded, and the pill has its own crash boundary.
- **Strings and theming:** English and Chinese dictionaries registered through the locale service under the plugin's namespace, styles built only from host theme tokens (with documented fallbacks where a token is not published), and no import of any Harness client package in the client half, which reaches the page's `react` through the module-loader factory.
- **Verification:** 65 Vitest cases in `test/index.test.ts`, `test/compaction.test.ts`, `test/settings.test.ts`, and `test/client.test.ts`; the declared release smoke check `test/smoke-release.ts`, which the release plan runs against the installed tarball and which evaluates the packaged `client.js` through a stub `window.__ModuleLoader__.load` with only `react` and `react/jsx-runtime` available; and a live `link:` install into the `web` profile, where the command, the Settings section, and the pill are exercised. `README.md` and `CHANGELOG.md` document all of it.
- **Release intent:** a hand-written `.changeset/dsh-autocompact-first-version.md` naming `@indexyz/dsh-autocompact` with `none`, because the package ships as its own first version `0.1.0`, which the plan publishes because it is absent from npm, so no bump is needed.

## Capabilities

### New Capabilities

- `autocompact-thresholds`: the session-scoped per-model threshold model, the `/autocompact` command that sets it, the optional global defaults in the bundle row's configuration, and the validation every threshold passes before it is accepted.
- `autocompact-compaction`: the `agent/pre-step` pressure check, how pressure is measured, how the balanced surface range is selected, how the backend is resolved for the exact agent, and how every failure is contained.
- `autocompact-settings-section`: the Settings section that edits the persisted per-model thresholds through the Host settings namespace, its state, its writability and conflict handling, its optional model catalog, its crash boundary, its strings, and its theming.
- `autocompact-status-pill`: the composer's ambient status entry, what it reads from projections, when it takes a seat, and how it opens the Settings section with the central panel as its fallback.
- `autocompact-package`: the package as a published artifact — manifest, two build halves and their committed output, the module-loader contract of `client.js`, the test suite and release smoke check, the live profile install, and the release decision.

### Modified Capabilities

None; this is the first change in `dsh-autocompact/openspec/` and it has no main specs yet.

## Impact

- **New files:** `dsh-autocompact/` in full — `package.json`, `LICENSE`, `README.md`, `CHANGELOG.md`, `cordis.patch.yml`, the host half (`index.ts`, `settings.ts`, `compaction.ts`), the client half under `src/client/` (`index.tsx`, `contracts.ts`, `services.ts`, `state.ts`, `config-store.ts`, `limits.ts`, `dictionary.ts`, `styles.ts`, `page.tsx`, `threshold-list.tsx`, `add-model.tsx`, `crash-boundary.tsx`, `status-dock.tsx`), the generated `lib/` and `client.js`, the tests under `test/` including `test/smoke-release.ts`, and `tsconfig.json`, `tsconfig.build.json`, `tsdown.config.ts`, `vitest.config.ts`, and `openspec/`.
- **Root:** the `dsh-autocompact` entry in `workspaces` and the release intent file `.changeset/dsh-autocompact-first-version.md`; nothing else at the root changes from this package's side.
- **Depends on:** `openspec/changes/support-dsh-packages/` — the `dsh-<topic>/` package class, the `release.smoke` field the release plan reads, and the root build step. Without it the package has no verification path and no release.
- **Published artifacts:** `@indexyz/dsh-autocompact@0.1.0` becomes the next upload from `main`. npm binds a trusted publisher in an existing package's settings, so the owner publishes that exact verified tarball once and then adds its trusted publisher (`docs/releases.md`, "First release of a new package"); agents never perform that step.
