# Design

## Context

See `proposal.md` — Why. Design-level current state:

- Two real-environment mechanisms already exist and set the pattern: `pi-skill/test/extension-load.test.ts` imports Pi's real loader (`loadExtensions` from the pinned `@earendil-works/pi-coding-agent` with an isolated `PI_CODING_AGENT_DIR`), and `dsh-thread-summary/test/host-integration.test.ts` mounts real services (`ctx.plugin(...)`) from the pinned 0.2.2-alpha.2 closure. The 0.2.2 audit proved why fakes hide the break: the `inject` list grew `"agents"` in the real service, and only a fixture that mounted real `AgentRegistry` reproduced it.
- The e2e runner (`scripts/e2e/plugins.ts`) already proves each dsh tarball by pack → isolated install → declared `release.smoke`. Its isolated install uses `--omit=peer --legacy-peer-deps`, a documented convention for resolving `"*"` peers against the registry — the runner is host _loading_, not unit testing; converting unit tests does not change the runner.
- Both `dsh-thread-summary` and `dsh-prompt-suggestions` already carry `@deepseek-ai/dsh-client-ui-primitives` at dev pin `0.2.2-alpha.2` / peer `"*"` (verified in their `package.json`; the package's `alpha` dist-tag is exactly `0.2.2-alpha.2`). `dsh-autocompact` does not, and does not need it: its built `client.js` requests only `react` and `react/jsx-runtime` (verified by grep against the artifact), so nothing there touches primitives.
- `jsdom ^30.1.3` is a dev pin of `dsh-prompt-suggestions` only; `dsh-thread-summary` and `dsh-autocompact` carry `react ^18.3.1` + `react-test-renderer ^18.3.1` but not `jsdom` (verified per workspace; `node_modules` trees contain only `@deepseek-ai/*`, tooling resolves from the root). A conversion that needs jsdom in those two packages needs a dev pin added — a manifest change, so it carries a `none` intent in the same commit.
- The primitives artifact is **not loadable outside its own build pipeline** (verified empirically): its `files` are `lib/index.js`, `lib/**/*.css`, `lib/types/**/*.d.ts`; `lib/index.js` bare-imports ~20 packages it declares only as devDependencies (`clsx`, `react-dom`, `shiki`, `@shikijs/langs`, `simple-icons`, `anser`, `katex`, `diff`, the `micromark-*`/`mdast-util-*` family, `@deepseek-ai/dsh-client-store`, `dsh-util-code-language`/`workspace-path`/`file-drag`), and it ships loose `.css` files its own code references. A scratch workspace pinning the full 28-package set installs cleanly (exit 0, 69 MB) yet `import()` still fails — `ERR_UNKNOWN_FILE_EXTENSION ".css"` — i.e. no amount of dev pins makes it Node-importable; only the web plane's bundle (its build inlines the CSS and its module table supplies the bare imports) can load it.
- Constraints: CI runs `npm run check` and `npm run test:e2e` with **no secrets** (lint.yml carries only `BASE_SHA`/`HEAD_SHA`; publish.yml only `github.token`); Zen's `/zen/v1/models` answers keyless 200 but completions return `401 AuthError: Missing API key` — no keyless chat route exists; the machine's local credential surface exists (`~/.dsh/.credentials.yaml`, fields: `version`/`records`/`refs`) but a CI secret grant needs the owner.
- The audit counted the mock usage precisely: `vi.mock` appears in 5 files; `vi.stubGlobal`/`vi.spyOn`/`vi.mocked` across ~20; hand-rolled fakes (`fakeSettings`, `mockLlm`, `fakeFetch`, `fakeEngine`, `ComponentStub`, `createElement` shims, `runInNewContext` + `__ModuleLoader__`) across ~25; `pi-model-trace` is the only package with no host-shaped test.

## Goals / Non-Goals

**Goals:**

- Every package test that today constructs its host from mocks instead exercises the host the package pins: same assertions about registration, mounting, commands, and events must hold when driven through the real plane.
- Keep the gate unchanged (`npm run check`, `npm run test:e2e`) and keep `release.smoke` (already real) untouched.
- Keep per-package conversion independently committable and revertible.

**Non-Goals:**

- `pi-provider-sub2api` live-endpoint conversions — deferred by explicit user decision; their stubbed tests stay, recorded as a known gap in docs.
- Credential-gated real model calls landing in CI — they land when the owner grants the key route (see Open Questions); until then no package converts its model seam by faking it or skipping silently.
- Changing `release.smoke`, the e2e runner's `--legacy-peer-deps` install convention, or any published content (test trees and docs only).
- Adding a root shared test harness or another test framework — each package keeps its own `test/` tree and its own `vitest.config.ts` (rule 2); existing `test/fixture.ts` stays as a per-package support module only if it stops mocking the host (usually: it must be deleted or rewritten).

## Decisions

1. **Unit tests drive the pinned host plane directly, not through pack→install.** Each package's `devDependencies` already contain the exact host packages (rule 3), so its tests import the real `@deepseek-ai/dsh-*`/`@earendil-works/*` packages from the installed workspace and mount them through the public `ctx.plugin` API — same graph the host builds. Alternative (pack→install per test) duplicates the e2e runner, is slow, and re-tests loading instead of behaviour.
2. **Real DOM, not stub DOM.** Client-half tests load the package's real built `client.js` and execute its one real `window.__ModuleLoader__.load({ id, factory })` registration against a real `window` from jsdom with real `react`/`react/jsx-runtime`. Primitives handling is bounded by what the artifact can actually load (see Context): `dsh-autocompact`'s client requests only `react` + `react/jsx-runtime`, so it is fully real with no primitives involved; `dsh-thread-summary` and `dsh-prompt-suggestions` request `@deepseek-ai/dsh-client-ui-primitives` as a module-table entry, and that entry cannot be produced by Node in any workspace (Context bullet 3) because the artifact ships unresolvable bare imports plus loose `.css`. The web shell's published bundle carries the real inlined factory (`@deepseek-ai/dsh-web-frontend@0.2.2-alpha.2`, whose `dist/assets/index--TtJvO-i.js` holds one module-table entry for it), so the faithful route for those assertions is driving the real web plane rather than a jsdom stand-in table; whether that route lands is an open item (tasks 3.3/3.4 record it as blocked today — `npm install @deepseek-ai/dsh-web-frontend@0.2.2-alpha.2` resolves 404 from npmjs despite the version metadata and tarball both returning 200, so the plane is not installable in a scratch workspace yet). Playwright over that plane is the heavier alternative; a jsdom plane that supplies a substituted `Switch`/`Button` factory is rejected outright as a stand-in component. Where a converted test cannot yet reach that plane, the primitives-backed assertion stays listed as blocked rather than stubbed. `react-test-renderer` and `jsdom` stay as _drivers of the real React/DOM_ — they exercise the real library rather than replacing it; the removed thing is the hand-rolled `ComponentStub`/fake-`createElement` layer.
3. **Network-shaped paths run against a real local server.** Each test starts a real `node:http` server in-process, and the code path performs its real fetch/undici call to it — URL routing, headers, aborts, and error statuses are exercised through the real client. Rejected: `vi.stubGlobal("fetch", …)` (that is the mock being removed) and live endpoints in `check` (credentials unavailable offline; see decision 5).
4. **Model seam: real stack, real settings, no injected stream.** Where a package streams through the real `ctx.llm` / pi-ai client, the test supplies the model via the settings under test (e.g. an `llm://` entry, or a provider registered with an explicit `baseURL` — `dsh-llm-pi-ai` supports `baseURL` + discovery/hand-entered models), never `vi.spyOn(stream)`. Where a credential is required, the credential comes from the host's own settings/credentials plane (locally `~/.dsh/.credentials.yaml`), never a hand-passed secret in code.
5. **No fake fallback and no silent skip.** If a credential-gated test runs without a credential, it fails loudly with the exact route it needs. CI today has no model key, so credential-gated model tests are _not converted into passing tests_ — the corresponding task stays blocked (see Open Questions + tasks 4.1) and CI stays green by not containing that test yet. This keeps the user directive literally true for everything landed.
6. **Docs surface updates exactly where the old mock contract lived:** `docs/conventions.md` "Tests" — the line "keep `index.ts` thin so most logic is testable **without a running Pi**" is contradicted by the new policy and gets rewritten (test through the running host); `docs/workflow.md` "Verify" gains what a real-environment run must load; the package table/README need no changes (no published content moves). AGENTS.md itself needs no edit if the rule text lands in `docs/conventions.md` Tests section as the index routes to (rule 5 already points at `docs/workflow.md`).
7. **Root release tooling keeps its recorded-world harness.** `scripts/release/test/*` and `scripts/e2e/test/*` stay on their world model (`publish-world.ts` and friends). These are the repository's own npm/registry/git adapters, not package tests; driving them against the real environment would publish packages from inside a test, which rule 11 forbids ("each action needs an explicit request"). This is a documented boundary, not a fake host: no package test uses it, and `npm run test:scripts` plus `npm run test:e2e` (real pack → isolated install → `release.smoke`) cover it from outside.
8. **Test support modules may be added under `test/`; they are never stand-ins.** The conversions added `test/host-plane.ts`, `test/local-server.ts`, `test/pi-host.ts`, `test/pi-rpc.ts`, `test/real-plane.ts`, `test/client-bundle.ts`, `test/jsdom.d.ts`, `test/provider-row.ts`, `test/rejecting-provider-row.ts`, `test/jsdom-types.ts`. Each composes or starts the real host (real loader/CLI/profile boot/`node:http` server/real Cordis row); none replaces a host module's behaviour. `test/` is in no package's `files` allowlist, so these stay unpublished and carry no release intent.

## Risks / Trade-offs

- [Real-plane unit tests are slower and couple to host internals' timing] → bound per-test cost in vitest config where needed; keep one mounted graph per test file via real composition, and prefer the package's public API surface over deep internals so coupling stays where the host already requires it (the `inject` list case shows the coupling is _the point_ of these tests).
- [dsh plane tests that construct sessions/filesystem in temp dirs mirror what real sessions do, but a real session directory carries format versions] → use the real session format packages from the closure (`dsh-session-format`, persistence) rather than hand-written session files; if a format-version gap appears, that is a finding to fix, not a stub.
- [jsdom differs from a real browser: no layout, no real paint, timers] → acceptable for asserting registration/DOM-shape/behaviour, which is what these tests assert today; the e2e runner still owns the loading proof. State this boundary in the converted test files' headers.
- [Removing `vi.restoreAllMocks`-style global restore patterns can leak real globals across test files] → each converted test gets scoped isolation by construction (fresh server, fresh mount), and any surviving global mutation is asserted, not restored-by-framework.
- [Local credential file shape (`version`/`records`/`refs`) is not the model-provider shape] → do not hand-decode credentials in tests; go through the host's provider/settings plane so the credential route is host-owned (a wrong decode would itself become a hidden stub).

## Migration Plan

1. Land the policy/docs surface first (group 1) so every later conversion is checkable against a written rule.
2. Convert package by package, disjoint trees, in this order (smallest known-good pattern first): `pi-skill`/`pi-continue`/`pi-model-trace`/`pi-autocompact` → `pi-custom-provider` → the four dsh packages (reuse the thread-summary host-integration pattern), `dsh-prompt-suggestions` last (most mock-shaped test files among dsh). One Conventional commit per package (`test(<scope>):` since `test/` is not published content), each verified by `npm run check --workspace @indexyz/<name>` plus the package's load check before committing.
3. After the last package lands, sync the delta specs into main specs and archive this change (skills `openspec-sync-specs` then `openspec-archive-change`, preserving `.openspec.yaml`).

- Rollback: any package commit reverts independently (`git revert`); the policy docs revert last so an in-flight conversion never runs against no rule.

## Open Questions

- **Credential route for Zen in CI (blocked until the owner answers):** chat completions need a key; the only CI routes are (a) an owner-granted repo secret + a test that reads it via the host's settings plane, or (b) an owner-provided keyless route. I verified Zen returns `401` keyless and cannot create secrets myself (`gh api repos/.../secrets` → 404, no access). Until answered, tasks 4.x stay pending and no package's model seam converts — this is recorded, not guessed.
- Whether `pi-skill`-style loader tests should also drive the _real_ Pi binary RPC path (already covered by e2e runner) in addition to the in-process real loader: deferred; the runner already owns that proof, and in-process loader testing is the real plane for registration behaviour.
