# Architecture

The repository layout and what the two plugin systems share. A package's own anatomy is in `docs/pi/README.md` or `docs/dsh/README.md`.

## Repository layout

```
.
├── AGENTS.md                      rules and router for agents
├── CLAUDE.md                      redirect to AGENTS.md
├── README.md                      human overview and package table
├── LICENSE                        MIT
├── docs/                          shared documents, plus pi/, dsh/, and releases/ details
├── openspec/                      OpenSpec root for repository-wide changes
├── .changeset/                    release intents (<id>.md), changesets config, changelog renderer
├── .github/workflows/             lint.yml (checks, release gate), publish.yml (publication), pi-host-rehearsal.yml (Pi upgrade rehearsal)
├── scripts/
│   ├── e2e/                       host loading for every plugin (`test:e2e`), and the black-box Pi suite in e2e/pi/ (`test:e2e:pi`)
│   └── release/                   release-impact gate, publication plan and publish steps, and their tests
├── .agents/skills/
│   ├── pi-extension-dev/SKILL.md  skill loaded when working on a Pi package
│   └── openspec-*/                OpenSpec workflow skills (generated by openspec init)
├── .claude -> .agents             symlink, so Claude Code reads the shared skills
├── pi-<topic>/                    one Pi package per directory, published as @indexyz/pi-<topic>
├── dsh-<topic>/                   one dsh package per directory, published as @indexyz/dsh-<topic>
├── package.json                   workspace root (private): workspaces, scripts, root dev tooling, pi manifest
├── package-lock.json              the only lockfile
├── tsconfig.json                  strictest compiler settings for scripts/ and .changeset/ (typecheck only)
├── .oxlintrc.json                 repository-wide lint rules
├── .oxlintrc.tooling.json         strict type-aware lint profile for scripts/ and .changeset/
└── .oxfmtrc.json                  formatter settings
```

The root `package.json` `workspaces` array is the list of packages. Its `pi` manifest lists every `./pi-*/index.ts`, so installing the whole repository from git loads every Pi package; dsh packages are installed into a dsh profile one at a time and are never listed there.

## What the systems share

The root never contains plugin runtime code. Node runs the tooling in `scripts/` directly from TypeScript through type stripping, so it has no build step, and nothing at the root is published or loaded by a host.

| Shared by both systems                                                                       | Consequence                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `npm install` and `package-lock.json`                                                        | A package's dependency change rewrites one lockfile; review that the other system's entries are untouched.                                                                     |
| oxfmt and oxlint configs                                                                     | Run them on the package directory for package work (`docs/workflow.md`, "Verify").                                                                                             |
| `scripts/release/`, `scripts/e2e/plugins.ts`, root `package.json`, `lint.yml`, `publish.yml` | A change here can reach both systems, so it is the case for the repository-wide gate.                                                                                          |
| CI                                                                                           | `lint.yml` runs root `npm run check`, `npm run test:e2e`, and `npm run test:e2e:pi`, and `publish.yml` runs root `npm run check`, so a failure in either system fails the run. |

Some root tooling serves only Pi: the black-box suite in `scripts/e2e/pi/`, the root `node-pty` dependency it needs, and `pi-host-rehearsal.yml`. They never touch a dsh package, and a change to them verifies only Pi (`docs/workflow.md`, "Choose the scope").

Everything else belongs to one package: its `package.json`, `tsconfig.json`, `vitest.config.ts`, tests, dev dependencies, pinned host, and OpenSpec root. Pinned host versions may differ between packages; npm then installs the differing version inside that package's own `node_modules/`.

## Release records

Release state lives in committed files and in the registry, never in CI configuration: release intents in `.changeset/<id>.md`, each package's version in its `package.json`, and its `CHANGELOG.md`. A push to `main` publishes every package version that npm does not have yet, built from the commit that introduced that version, and records each published version with a `@indexyz/<name>@<version>` tag and a GitHub Release. `docs/releases.md` has the procedure.
