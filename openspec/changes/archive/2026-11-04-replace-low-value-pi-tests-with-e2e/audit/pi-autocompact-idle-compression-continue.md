Pinned host: `@earendil-works/pi-coding-agent` 1.5.0. Read-only audit; `git status` is unchanged by it. Running vitest and the bin may have refreshed git-ignored caches under `node_modules`.

### Defects found (both reproduced against the published bin, both invisible to current tests)

**D1. `/continue` does nothing in print and JSON modes (upstream #11011, closed NOT_PLANNED).**
`pi -p /continue` on an aborted session: exit 1, stderr `Request aborted`, **0 model requests**. `pi --mode json /continue`: **exit 0**, stdout is only the session header, **0 model requests** (silent). Cause: `pi-continue/index.ts:96` calls `pi.sendMessage(..., { triggerTurn: true })` and the handler returns, so the CLI disposes the session. Upstream will not fix it, so the package has to. A patched copy outside the repo with `await ctx.waitForIdle();` after the `sendMessage` call passed both modes: exit 0, one model request, retried turn persisted. `continue.test.ts` is RPC-only, so it cannot see this.

**D2. Autocompact boundary summaries silently lose reasoning effort and the output token limit.**
Captured request bodies on a `reasoning: true` model at thinking level `high`:

```text
autocompact boundary summary: {"model":"m","stream":true,"stream_options":{"include_usage":true},"store":false}
native compaction summary:    {...,"store":false,"max_completion_tokens":4096,"reasoning_effort":"high"}
```

Request shape is verified. Cause is inferred from the types and docs: `pi-autocompact/compaction.ts:51` passes `ctx.modelRegistry.stream` as `generateSummaryWithUsage`'s `streamFn`. `StreamFn` is typed for `SimpleStreamOptions` (`pi-agent-core/dist/types.d.ts:17`) and the summarizer sets `options.reasoning` (`createSummarizationOptions`), while `extensions.md:1222` says `streamSimple` is the path for `reasoning`. So `ctx.thinkingLevel` at `compaction.ts:50` has no effect on this path. I did not run a `streamSimple` fix. The README says boundary summaries use the "standard Pi summary generator"; the in-process tests only count summary requests and never read their options.

### Design observation, not a defect verdict

`checkBoundary` (`pi-autocompact/index.ts:105`) ignores `event.outcome`. Scenario H (retry disabled): a turn failed with HTTP 500, then autocompact immediately sent a paid summary request and appended a compaction after the error turn. `/continue` still retried correctly afterwards. Pi's own example at `extensions.md:728` filters on `outcome`. I did not test this with Pi's auto-retry enabled.

### Coverage gaps the verdicts cannot fix

- **G1. No real tool calls in any suite.** All three planes run with no tools (`noTools: "all"`, `--no-builtin-tools`). The local servers cannot emit `tool_calls`. So autocompact's core promise ("after tools finish", complete assistant/tool-result groups) and pi-continue's ("retries from the preceding user message or tool result") have no real-host coverage. Only `compaction.test.ts:60` covers the planning logic.
- **G2. `agent_before_settle` never does the work in any test.** `turn_end` always acts first in the same run; settle then returns early. The only other reference is the registration list, which this audit deletes. Exercising it needs a fixture that moves the leaf after a failed `turn_end` attempt.
- **G3. `npm run test:e2e` proves less than its name suggests.** `checkPi` (`scripts/e2e/plugins.ts:130-144`) asserts only that `get_commands` returned `success: true`. It does not check that the package's command is listed. Deleting the load tests here is still safe because every behaviour test fails if the extension does not load, but do not treat this script as a load assertion.
- **G4. Value imports from the host only fail at use (inferred).** Autocompact imports `generateSummaryWithUsage` and `estimateTokens` as values. A load-only check does not call them, so a missing export would show up at the first boundary rather than at load. `generateSummaryWithUsage` is present in `dist/bundle/index.js` (grep), and both work through the bin today (A).
- **G5. Other untested paths.** Session-start error notice for invalid autocompact settings (spec: "Invalid percentage"); Esc during a boundary summary; idle `hasPendingMessages`, `isIdle`, and null-usage guards at the moment the timer fires.
